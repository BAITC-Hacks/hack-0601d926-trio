# Методология и ограничения

Результат предназначен для выбора порядка проверки. Роль, role score и priority score не являются вероятностью преступления, доказательством виновности или подтверждённой клиентской характеристикой. Правильных размеченных ролей нет: используются проверяемые эвристики.

## Наблюдение

Выборка строится только по исходящим внутрибанковским переводам от 81 seed до четырёх колен. Период — июль 2026, нижняя граница суммы — 5 000 KZT. Входящие платежи извне выборки, межбанковские переводы, остатки, малые операции и последующие периоды отсутствуют. Полный баланс неизвестен. Seed — контекст исходной выборки, а не результат новой классификации.

- Depth=4 отмечается `boundary_censored`; отсутствие исходящих рёбер не позволяет присвоить terminal.
- Для seed `pass_through` и `retention_proxy` имеют значение null; балансовые правила transit и terminal отключены.
- `outflow > inflow` допустимо: ранее существовавший остаток и внешние поступления неизвестны.
- Изолированные nodes сохраняются. Несвязанные компоненты никогда не объединяются в кластер.
- Совпадающие операции сохраняются с предупреждением: без transaction ID невозможно доказать дублирование.
- ФИО, ИИН, возраст, доход, назначение платежа и другие отсутствующие атрибуты не генерируются.

## Метрики

Направленные степени показывают число уникальных отправителей/получателей. Fan-in/out исключают сам узел, чтобы самоперевод не считался независимым контрагентом. Суммы и число операций считаются отдельно по направлениям. Среднее и медиана — по наблюдаемым операциям с участием узла. Самоперевод учитывается один раз при среднем и активности, но присутствует в обоих направленных потоках.

`pass_through = out_sum / in_sum`, если in_sum > 0 и узел не seed. Значение может превышать 1. `retention_proxy = max(0, 1 − pass_through)`: это только доля наблюдаемого входа без наблюдаемого выхода, не остаток.

PageRank взвешен суммами. HITS вычисляется детерминированной степенной итерацией с весами log1p суммы; hub отражает структурную позицию отправителя, authority — получателя. Betweenness использует направленные пути по числу переходов: сумма перевода не интерпретируется как расстояние. Для графа более 256 узлов используются 256 стартовых вершин с seed=42.

Связанные seed — объединение различных seed, достижимых выше или ниже узла по направленным путям; сам узел исключается. Минимальное расстояние считается от seed по направлению денег. Отдельно доступны количества seed, достижимых от узла и ведущих к нему. Межкластерное посредничество — доля инцидентных рёбер между сообществами. Циклы определяются сильносвязными компонентами и петлями; возвратные потоки — наличием обратного ребра. Повторяемость маршрута — доля операций на парах с более чем одной операцией; это proxy повторения, а не восстановленная цепочка конкретных денег.

Концентрация контрагентов — HHI, сумма квадратов их долей в наблюдаемом обороте. Для распределения отдельно используется HHI исходящего потока. Значение ближе к 1 означает концентрацию на небольшом числе контрагентов.

## Время

FIFO последовательно сопоставляет поступления с более поздними списаниями. Каждая сумма расходуется не более одного раза. Старые поступления также погашаются, но только списания через 1–2 дня входят в `rapid_transit_share`. Для дат без времени операции одного дня не сопоставляются, поскольку порядок неизвестен. Самопереводы исключены из этого сопоставления. Показатель описывает совместимость потоков во времени, а не доказанное происхождение средств. Конец месяца может скрывать дальнейший выход денег.

## Нормализация и роли

Нулевые показатели остаются нулём. Положительные значения переводятся в средний процентильный ранг; одинаковые значения получают одинаковый ранг. Нормализованные fan-in/out насыщаются при 6 контрагентах. Составная центральность — среднее рангов PageRank, betweenness и максимума HITS hub/authority.

Все параметры находятся в `backend/app/analytics/config.json`. Таблица ниже фиксирует настройки поставки:

| Роль | Условие допуска | Взвешенные признаки |
|---|---|---|
| consolidator | ≥3 отправителя | 0,40 fan-in + 0,20 ранг входа + 0,20 доля входящей степени + 0,20 удержание |
| transit | не seed; вход и выход; быстрый транзит ≥0,15 | 0,30 сопоставимость потоков + 0,40 быстрый транзит + 0,15 низкое удержание + 0,15 двусторонность |
| distributor | ≥3 получателя | 0,55 fan-out + 0,20 ранг выхода + 0,15 дисперсия контрагентов + 0,10 ранг hub |
| terminal | не seed, не depth=4, есть вход, out/in ≤0,10 | 0,55 удержание + 0,25 ранг входа + 0,20 узкий fan-in |
| coordinator | вход и выход, ≥4 ветки, ≥2 связанных seed, центральность ≥0,60, есть межкластерное ребро | 0,40 центральность + 0,25 межкластерная доля + 0,20 ранг seed + 0,15 двустороннее ветвление |
| peripheral | резервная гипотеза | max(0,24; 1 − максимальный score других ролей) |

Непрошедшие условия роли получают score 0. Основная роль — максимальный score. При точном равенстве порядок: consolidator, transit, distributor, terminal, coordinator, peripheral. Этот порядок фиксирован и не зависит от gid.

`role_score = (0,60 × лучший score + 0,40 × отрыв от второго) × Q`.

Q — качество наблюдения. Базовое значение 1; для изолированных узлов 0,35, при менее 3 наблюдаемых участий в операциях 0,65. Далее множители seed 0,90 и depth=4 0,70. Ограничение видимости уменьшает уверенность и приоритет, но не скрывает клиентов.

## Приоритет и объяснения

`priority_score = Q × Σ(weight × factor)`.

| Фактор | Вес |
|---|---:|
| Значимость роли × максимальный исходный role score | 0,20 |
| Ранг количества связанных seed | 0,16 |
| Составная центральность | 0,14 |
| Ранг наблюдаемого оборота | 0,12 |
| Ранг количества веток | 0,10 |
| Доля межкластерных рёбер | 0,10 |
| Максимум признака цикла и повторяемости маршрутов | 0,06 |
| Быстрый транзит | 0,06 |
| Q как отдельный фактор полноты | 0,06 |

Значимость ролей: coordinator 1; consolidator 0,90; transit/distributor 0,85; terminal 0,65; peripheral 0,10. Ролевой фактор приоритета использует исходный score победившей роли; отдельный `role_score` в карточке учитывает отрыв от второго score и Q. Полнота Q входит в приоритет общим множителем и отдельным фактором: это консервативная эвристика, а не калиброванная вероятность. Вклады API уже включают общий множитель Q и в сумме равны priority_score. Порядок сравним внутри текущего снимка; новые данные могут менять ранги.

Короткое evidence содержит до 200 символов и конкретные числа. Подробная карточка показывает исходные метрики, все role scores, ограничения и следующий запрос данных. Термин «получатель» описывает наблюдаемое окно и требует проверки более полных выписок.

## Кластеры

Каждая слабосвязная компонента обрабатывается отдельно. Компоненты менее 12 узлов остаются одним кластером. Для больших компонент Louvain применяется к неориентированной проекции: `weight = log1p(sum_kzt) + 0,25 × log1p(n_tx)`, встречные рёбра суммируются; resolution 1,15, seed 42. Направление сохраняется для метрик и всех денежных агрегатов. Номера сообществ стабилизируются по минимальному gid и могут меняться при изменении сети.

Гипотеза кластера определяется по наиболее приоритетному непериферийному узлу. Показываются все роли, ключевые gid, внутренний оборот и межкластерные потоки, чтобы аналитик мог оценить такую упрощённую гипотезу.

Алгоритм сообществ сверялся с [официальной документацией NetworkX](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.community.louvain.louvain_communities.html).
